## 1. Solution Overview

The No-PO Invoice Chaser queries Coupa daily for unpaid invoices without linked purchase orders, excludes credit notes, and sends a Slack Block Kit message to the AP SME if any are found. Trigger: weekday schedule at 10:00 Europe/Bucharest. No records are modified in Coupa; on zero-count days the workflow completes silently. Outcome: on-demand visibility into no-PO invoice volume to enforce the no-PO-no-pay payment policy.

| Project | Role | Entry Point | Trigger |
|---|---|---|---|
| `code/no-po-invoice-chaser-803/no-po-invoice-chaser-api` | primary | API Workflow | Orchestrator schedule, weekdays 10:00 EET |

## 2. As-Built Architecture

Single API Workflow project with no dispatcher/performer split. Workflow retrieves invoices from Coupa via HTTP connector, filters by date window and PO linkage in a JavaScript step, and posts a Slack Block Kit message if qualifying invoices exist.

```
Orchestrator Schedule (weekday 10:00)
        ↓
API Workflow: no-po-invoice-chaser-api
  ├─ Compute date window (JS)
  ├─ HTTP GET Coupa /invoices (status: draft,new; past 7 days)
  ├─ Filter & count (JS: exclude credit notes; check line-item PO)
  ├─ Branch: if count > 0
  │   ├─ Compose Block Kit payload (JS)
  │   ├─ HTTP POST Slack chat.postMessage
  │   └─ Validate response.ok
  └─ Log result & return {status, qualifying_count, slack_sent}
```

**As-built match to SDD:** All activities, variable names, and filter logic are present as specified. The JavaScript filter at `code/no-po-invoice-chaser-803/no-po-invoice-chaser-api/Workflow.json:213–228` checks both `po-number` and `order-header-num` fields on each invoice line; missing or whitespace-only values are treated as no linked PO. Credit note exclusion is checked by `invoice-type === 'Credit Note'` at line 215. The Slack response validation at line 373 throws on `resp.ok !== true`, halting the run with no retry. Zero-count branch (line 409) is an empty Else clause per BR-07.

## 4. Exception and Error Handling

| Error ID | Trigger | Handler | Retry | Outcome |
|---|---|---|---|---|
| S1 | Coupa HTTP error (401/403/5xx) | Thrown by HTTP activity; caught by Workflow runtime | None | Run fails; error logged; no Slack sent (BR-09) |
| S2 | Coupa timeout | Thrown by HTTP activity | None | Run fails; error logged; no Slack sent |

| S5 | Credential/connection unavailable at runtime | Orchestrator alert; HTTP activity unavailable | None | Run fails; credential error in Orchestrator logs |
| S6 | Unhandled exception in any JS block | Thrown; caught by Workflow runtime | None | Run fails; stack trace logged |

## 5. Operations Runbook

### Trigger and Schedule
- **Weekday schedule:** Monday–Friday, 10:00 Europe/Bucharest (EET/EEST)
- **Manual start:** POST to API Workflow entry point (no input required); variables initialized to defaults
- **Expected runtime:** 3–8 seconds (network-dependent; Coupa + Slack latency)
- **Typical volume:** 1–20 qualifying invoices per run on active days; 0 on clean days

### Normal Run Signature
```
Log output:
  qualifying_count=<N>
  slack_sent=<true|false>

HTTP 200 response body:
  {"status": "Successful", "qualifying_count": <N>, "slack_sent": <true|false>}
```
- **Count > 0:** Slack message posted to WLX9BD8FN with Block Kit header, policy context, Coupa link button, and footer date range.
- **Count = 0:** No Slack message sent; `slack_sent = false`; run succeeds silently.

### Prerequisites (before first run)
- ✓ Integration Service connections exist and are authorized:
  - `coupa-uipath-test` (Coupa API read-only invoice scope)
  - `slack-product-test-app` (Slack Bot API token, chat.postMessage capability)
- ✓ Orchestrator timezone set to Europe/Bucharest
- ✓ Slack member WLX9BD8FN exists and can receive direct messages (confirm with SME)
- ✓ Coupa hostname in Slack button URL: verify production hostname (SDD notes `uipath-test.coupahost.com` is example; change to production before deployment)

### When It Breaks

| Symptom | Check |
|---|---|
| Run fails with `Slack chat.postMessage failed: {...}` | Verify Slack connection is authorized; check `slack-product-test-app` token is not expired |
| Run fails with Coupa error (4xx/5xx) | Verify Coupa connection is authorized; check API key/OAuth scope includes invoice read; confirm Coupa host is reachable |
| Run completes but no Slack message appears; `slack_sent = false` | Check qualifying_count in logs: if 0, behavior is correct (BR-07). If > 0, Slack validation failed — check logs for HTTP error detail |
| Workflow times out (runtime > 30 seconds) | Reduce Coupa query limit or increase network timeout in connector settings; check Coupa server load |
