## 1. API Workflow Overview

The No-PO Invoice Chaser is a weekday automation that queries Coupa for invoices with no properly linked purchase order and notifies the AP SME by Slack if any are found. Trigger: Orchestrator schedule, weekdays only, 10:00 Europe/Bucharest. 

Process: retrieve invoices from Coupa with status draft or new, dated within the past 7 calendar days; apply exclusions (credit notes) and validation (PO linkage on invoice lines, not description only); count the qualifying invoices; if count > 0, send one Slack Block Kit direct message to Slack member WLX9BD8FN containing the count, policy context, action request, and a filtered Coupa URL for the date range; if count = 0, complete silently with no notification. 

No records are created or modified in Coupa. No retry or fallback behavior on error: a failed system call is a failed run. Outcome: a Block Kit DM with the count and action button (if count > 0) or silent success (if count = 0).

## 4. Execution Flow

| Step | Activity | Purpose | Output |
|---|---|---|---|
| 1.1 | WorkflowStart | initialize | variables reset to defaults |
| 1.2 | Javascript: compute dates | derive 7-day window | windowStart, windowEnd, runDate |
| 1.3–1.5 | Assign × 3 | alias outputs | set variables from script |
| 1.6 | HTTP_Request_Coupa | query invoices, status IN (draft,new), date range | JSON array of invoice objects |
| 1.7 | Javascript: filter & count | exclude credit notes; check line-item PO; count qualifying | qualifyingCount (int), exclusionLog |
| 1.8–1.9 | Assign × 2 | alias outputs | set variables |
| 1.10 | If: count > 0 | branch on qualifying list | then → compose & send; else → skip |
| 1.11 | Javascript: compose Slack payload | build Block Kit JSON with substitutions | slackPayload, coupaUrl |
| 1.12–1.13 | Assign × 2 | alias outputs | set variables |
| 1.14 | HTTP_Request_Slack | POST chat.postMessage with Block Kit body | Slack response |
| 1.15 | Javascript: validate Slack | check response.ok = true; throw if not | confirms delivery or fails run |
| 1.16 | Assign | flag success | slackSent = true |
| 1.17 | Javascript: log result | console.log qualifying_count, slack_sent | output values for Orchestrator |
| 1.18 | Response | return final status | {status, qualifying_count, slack_sent} |

**Business rules implemented:**
BR-01, BR-02: PO linkage on invoice lines (not description only). BR-03: credit notes excluded. BR-04: status draft/new, past 7 days. BR-05: count only, no detail. BR-06: Block Kit DM to WLX9BD8FN. BR-07: zero count → silent. BR-08, BR-09: no retry; error → failed run, no Slack message.

## 6. Error Handling

| Failure | Detection | Response |
|---|---|---|
| Coupa 401/403 | statusCode not 2xx | throw; fail run; no Slack (S1, BR-09) |
| Coupa timeout or 5xx | statusCode not 2xx | throw; fail run (S2, BR-09) |
| Slack non-2xx or validation fail | HTTP response or script throw | throw; fail run (S3, BR-08) |
| Credential missing/expired | runtime unavailable | throw; Orchestrator alert (S5) |
| Unhandled exception | uncaught error | throw; stack to log (S6) |

No retry — BR-08 excludes it. Failed call = failed run; BR-09: no second message path exists.

## 8. Testing Strategy

### Happy Path
- Schedule fires weekday 10:00 Europe/Bucharest; Coupa returns invoices; qualifying_count > 0
- Slack DM delivered with header, policy section, Coupa link button, footer dates
- Output: {status: "Successful", qualifying_count: N, slack_sent: true}

### Business Exceptions
- Zero qualifying invoices: silent; slack_sent = false (BR-07)
- Credit note found: excluded from count; logged (BR-03)
- Description-only PO: treated as missing; counted (BR-02)

### System Errors
- Coupa auth / query error: fail run; log error; no Slack (S1, S2, BR-09)
- Slack delivery error: fail run; no retry (S3, BR-08)
- Credential missing: Orchestrator alert; run fails (S5)
